## Worum es geht

Der Dispatcher sendet bewusst nacheinander in offener Transaktion (ein Broker-Roundtrip pro Nachricht). Paralleles Senden würde nach einem Teilfehler einen älteren Snapshot hinter einen neueren setzen (kompaktiertes `instruments.v1`). Begründung als `ponytail:` im Code.

## Wo

`src/Instruments/Portal.Instruments.Infrastructure/Outbox/OutboxDispatcher.cs`

## Vorschlag

Nur angehen, wenn die Outbox sich messbar staut. Dann z. B. pro Key nacheinander, über Keys parallel senden, oder die gesendeten Zeilen einzeln markieren. Ordnung pro Key muss erhalten bleiben (Test `Sends_in_insert_order_even_when_the_app_clock_disagrees`).

## Fertig, wenn

- [ ] Höherer Durchsatz bei gleicher Ordnung pro Key; bestehende Tests grün.
