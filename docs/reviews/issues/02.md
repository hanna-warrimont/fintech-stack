title: Node 24 überall, damit die package-lock.json stabil bleibt
labels: bug,prio: hoch,bereich: frontend,review-2026-11-15
---
## Worum es geht

Aspire führt beim Start des Frontends `npm install` aus. Mit npm 11 (Node 24+) wird `package-lock.json` dabei so umgeschrieben, dass `npm ci` auf Node 22 scheitert (`Missing: crossws … from lock file`). CI und Dockerfile nutzen Node 22. Das hat die CI schon einmal gebrochen (Fix `ed021a7`).

## Wo

`.github/workflows/ci.yml` (node-version), `src/Frontend/Dockerfile`, `src/Frontend/package.json`

## Vorschlag

Überall Node 24 (aktuelles LTS): CI, Dockerfile (`node:24-alpine`), dazu `"engines": { "node": ">=24" }` und `packageManager` in `package.json`. Lockfile einmal mit npm 11 neu erzeugen.

## Fertig, wenn

- [ ] Ein lokaler AppHost-Start verändert `package-lock.json` nicht mehr; CI grün.
